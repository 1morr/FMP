# M2 PR 19：右側「正在播放」面板

依據：
- M2 `design.md` §9.4（面板）、§9.2（播放列）、§3.4（`layout_state`）、§9.3 的 PR 18a 決定（「⋯」的面板開關）；
- ADR 0024 §決定 3（面板在寬度 ≥ 840 常駐，U7）、§決定 6；
- 依賴 PR 18a（`layout_state` 的 `panel_expanded`、`panel_width` 已建好，`TrackDetails` 已有）。

這是 M2 的最後一個 PR。

## 目標

整個視窗 ≥ 840（expanded 以上）時，外殼內容區的右側常駐一個「正在播放」面板，顯示目前這首的 `TrackDetails`。面板：
- 可以收起與展開；
- 可以拖寬，鍵盤也能調；
- 收起狀態與寬度依裝置記住。

## 要做的

### 版面（`lib/ui/shell/`）

- **出現條件**：整個視窗的 `WindowClass` 是 expanded 以上，而且面板沒有收起。compact、medium 沒有面板，也沒有開關。
- **位置**：內容區（搜尋、歷史、設定）與面板左右並排，中間是拖曳把手。
  - 播放列在兩者下方、橫跨內容與面板，所以開關面板不改變播放列的分段（design §9.2）。
  - 內容區的 `WindowClassScope` 量到的是扣掉面板後的寬度，頁面依實際寬度排版。
- **焦點**：面板與把手屬於「內容」焦點區（design §9.4），F6 的三區不變。
- **內容**：
  - 標題列：「正在播放」，加一個收起鈕（只有圖示，以 tooltip 當名稱）；
  - 下面是 `TrackDetails`（與播放頁「詳細」同一個 widget）；
  - 佇列是空的時，顯示空狀態「沒有正在播放的歌」。
  - 面板底色用主題的 surface 系列，不用毛玻璃：毛玻璃只在播放頁（ADR 0024 §決定 1）。

### 寬度與拖曳

- **範圍**：下限 320dp，上限為視窗寬 × 0.4。預設 412dp，extraLarge 預設 480dp（design §9.4，舊版的數字）。
  - 上限低於下限時以下限為準（例如視窗 840 時上限 336，範圍是 320–336）。
  - 數值放 `AppLayout`。
- **夾取**：每次排版時依目前視窗夾取。只夾畫面上的寬度，不改寫記憶的值；資料庫已經擋了 > 1600 的壞值。
- **把手**（M3 可調寬 pane 的 drag handle）：
  - 滑鼠拖曳時游標是左右調整；拖曳中只改畫面，放開才寫入 `layout_state.panel_width`。
  - 可以用鍵盤聚焦：←／→ 一次調 16dp，夾在範圍內，每按一次就寫入。
  - tooltip「拖曳或按 ←／→ 調整寬度」，三語言。語意是可調整的分隔線，有名稱與目前寬度。
- **方向**：面板在右，所以把手往左拖面板變寬。鍵盤照畫面方向：← 讓把手往左、面板變寬，→ 讓面板變窄。

### 收起與展開

- **記憶**：存在 `layout_state.panel_expanded`。沒記過是展開（design §9.4：預設展開，照 ADR「常駐」）。
- **三個入口**，都切換同一個值並寫入：
  1. 面板標題列的收起鈕，tooltip「收起正在播放面板」。
  2. **播放列的開關鈕**（擁有者決定，照 Spotify 的「正在播放」鈕）：
     - 只在整個視窗 ≥ 840（面板可能出現）時有。
     - 播放列 ≥ 840 那一段：右側裝置鈕前面多一顆圖示鈕，表示面板開著或收起。tooltip 依狀態是「顯示正在播放面板」或「隱藏正在播放面板」。
     - 播放列 600–839 那一段（視窗 840 而播放列較窄時會發生）：放進那一段的「⋯」選單，作為一個勾選項。
     - 播放列 < 600 不會遇到：視窗 ≥ 840 時播放列至少 760。
  3. **播放頁「⋯」**：expanded 以上的版面多一個勾選項「正在播放面板」（design §9.3「⋯」的面板開關，18a 留下的）。compact、medium 沒有這一項。
- 收起時面板與把手都不佔位置。

### 資料層

- `LayoutStateRepository` 加讀寫 `panelExpanded`、`panelWidth`：`LayoutState` 加兩個欄位，`write` 加兩個參數，沒給的不動。
- 18a 的分頁讀寫不變。
- 不升 schema，欄位在 v6 已經建好。

### 文件

- `app/AGENTS.md` § 介面：面板（出現條件、寬度範圍與夾取、拖曳只在結束寫入、鍵盤、三個開關入口、焦點區、播放列分段不受影響）。每條寫出閘門。
- § 資料層 `layout_state` 那條：把「面板兩欄 PR 19 接上」改成現在的行為。
- `.trellis/spec/app/ui/index.md`：需要時更新。

## 驗收

- **出現條件**：
  - 視窗 839 沒有面板、沒有開關，840 有；
  - compact、medium 沒有；
  - 收起時面板與把手都不在；
  - 佇列空的時顯示空狀態。
- **寬度**：
  - 預設 412、extraLarge 480；
  - 資料庫的值被夾到 [320, 視窗 × 0.4]，例如記住 900 而視窗 1000 時顯示 400；
  - 視窗 840 時上限低於 412，取 336；
  - 視窗縮放時跟著夾，記憶的值不變。
- **拖曳**：拖曳中不寫入，放開寫入一次。用 `TestGesture`，寫入次數以假的 repository 或查表斷言。往左拖變寬、往右拖變窄，夾在範圍內。
- **鍵盤**：把手可聚焦，←／→ 各一例：16dp、夾取、寫入。
- **開關**：
  - 標題列的收起鈕、播放列的圖示鈕（≥ 840 段）、播放列「⋯」的勾選項（600–839 段）、播放頁「⋯」的勾選項（expanded 以上才有）都會切換並寫入 `panel_expanded`；
  - 重開 App 仍記得；
  - 開關面板時播放列的分段不變。
- **焦點**：F6 的三區不變，面板在內容區之內；把手在 Tab 順序裡。
- **資料層**：`layout_state_repository_test.dart` 加兩個欄位（`stored format`、`write` 沒給的不動、`watch`）。
- **guideline**：淺色、深色 × 1000、1800 寬的外殼，有面板、有歌，加進 `test/ui/guidelines_test.dart`。
- **golden**：外殼 1000、1800 寬有面板（新的 golden 測試或加進既有的外殼 golden）。`player_bar` 的 golden 多一顆鈕要重產。`--update-goldens` 後由主對話看圖。
- **本機**：
  - `dart format`、`dart analyze --fatal-infos`、`flutter analyze`、`flutter test` 全綠；
  - Windows 跑 `toast_layering_test.dart`（改到外殼）。整合測試會把 `build/windows/x64/dev/runner/Debug/fmp.exe` 換成測試入口，跑完要 `flutter build windows --flavor dev --debug`。
- **實機**（重播，測試插件；主對話做）：
  - Windows：
    - 拖寬；
    - 收起與展開（三個入口）；
    - 重啟後維持；
    - 縮到 < 840 時面板消失，放大回來仍是記住的寬度；
    - 鍵盤調寬。
  - Android：平板尺寸的模擬器或手機橫向（內容區 ≥ 840 的情況）至少看一次 expanded。
