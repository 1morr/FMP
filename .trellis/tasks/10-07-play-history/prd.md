# M2 PR 15：播放歷史與「歷史」頁

M2 `design.md` §7.8、§9.7、§7.3（歷史那一列）、§3.1–§3.3、§6、§9.1（導覽三項）；決定 5；E15。依賴 PR 10（臨時播放）與 PR 14（`tracks`、恢復）。

## 目標

每次真的開始聽一首歌，就記一筆播放歷史。使用者從「歷史」導覽項按日期回看，點一筆就臨時播放；也能移除單筆、清除全部，並設定保留多少筆。全部離線可用。

## 要做的

### 資料層（schema v4 → v5）

- `play_history` 表：`id` int 自增主鍵、`track_key` FK → `tracks`（`RESTRICT`）、`played_at` int（unix 毫秒）。索引建在 `played_at`，`track_key` 也要建（PR 14 的教訓：沒有索引時，孤兒清理的 `RESTRICT` 檢查每刪一首都要掃整張表）。
- 照 `.trellis/spec/app/data/index.md` § 改 schema 的完整流程：v5 快照、`stepByStep`、三種 migration 測試，並有 `RESTRICT` 的 cascade 反例測試。
- `PlayHistoryRepository`：
  - 寫一筆：同一個 transaction 裡先 upsert `tracks`，再插入一列，然後裁掉超過保留筆數的最舊列；
  - 依 `played_at` 倒序分頁讀，同時取曲目的顯示資料；
  - 刪一筆（依 `id`）；
  - 全部清除；
  - 照保留筆數裁切（改小設定時用）；
  - 一個 stream 或計數，讓歷史頁在新增或刪除後更新。
- 孤兒清理（啟動維護的 `orphan-tracks`）也要排除被 `play_history` 參照的曲目，並有測試。

### 寫入時機（design §7.8）

一次「開始一首」在第一次進入 `ready`（出聲）時寫一筆。

| 算一筆 | 不算 |
|---|---|
| 換歌：下一首、上一首、跳到某首、播完往下 | 同一次開始裡的重試、重新解析、換候選 |
| 臨時播放 | 啟動恢復後的第一次播放（`startedFromRestore`；包括恢復後先臨時播放、再按播放的那次，PR 14 的擁有者決定） |
| 前瞻接上（交接） | 臨時播放結束、回到佇列那一首（從快照位置續播） |
| 單曲循環的每一圈：前瞻接上與 `RepeatTrack` 都算 | 「上一首」在播放超過 3 秒時回到這首開頭（`RestartTrack`，等於 seek） |
| | 暫停後繼續、seek |
| | 輸出裝置失敗後按播放，從原位置重新開流 |
| | 一直沒出聲就換走或失敗的那首 |

- 控制器只對外報「這一首算一次播放」：一個 stream 或回呼，帶 `TrackInfo` 與時間。由 `lib/playback/` 裡的記錄者接上 repository；控制器不 import 資料層，照 `QueueStore` 的分工。
- 時間取自可注入的時鐘，測試用假時鐘。
- **寫入失敗不影響播放**：`log.report`，不提示。

### 設定

- `PlaybackSettings.playHistoryLimit`：欄位在 v3 已經預留；預設 10000，選項 1000／5000／10000／50000。
- setter 與設定頁「播放」組的一列，放在 design §3.3 的欄位順序。
- 改小時當下裁切。三語言。

### 外殼與歷史頁

- **導覽三項**：搜尋｜歷史｜設定。三種導覽元件照 M1 的 `navigation per window class` 測試，改成三個導覽項。
- **歷史頁**（`lib/ui/history/`）：
  - 依時間倒序，以日為組：今天、昨天，之後是日期，跨年才帶年份。日期與時刻依介面語言格式化，日界依裝置的本地時間。
  - 每一列：封面、標題、副標「作者 · 播放時刻（HH:mm）」（擁有者決定）。
  - 用 drift 分頁查詢加 `ListView.builder`，一萬筆不一次載入。
  - 點一下是臨時播放（D1）。
  - 選單（右鍵、長按、尾端「⋯」）：播放、下一首播放、加入佇列、從歷史移除。**只移除這一筆**（擁有者決定），不跳提示。
  - 標題列有「清除全部歷史」：先跳確認框，確認後清除，並以統一提示（ADR 0023）顯示「已清除播放歷史」（擁有者決定：只有清除全部才提示）。
  - 沒有紀錄時顯示空狀態。
  - 離線時完整可用，封面讀不到就顯示佔位圖（design §5 的表）。
  - 加進 guideline 測試。
- 不做舊版的搜尋、統計、排序、多選、日期篩選、折疊分組（M2 範圍外）。

### 文件

- `app/AGENTS.md`：資料層（`play_history`、孤兒定義）、播放（歷史的寫入時機與閘門）、UI（導覽三項、歷史頁）。每條都寫出它的閘門。
- 需要時更新 `.trellis/spec/app/{data,playback,ui,settings}/`。

## 驗收

- **寫入時機**，各自有測試：
  - 換歌、前瞻接上、臨時播放、單曲循環每圈（前瞻接上與 `RepeatTrack` 兩條路）各寫一筆；
  - 重試、換候選、啟動恢復（含恢復後先臨時播放）、回到佇列、`RestartTrack`、暫停後繼續、沒出聲就換走，都不寫。
  - 這同時對應 ADR 0018 §如何確認「單曲循環每圈一筆歷史且不重解析」。
- 保留筆數的裁切：寫入時裁、改小時裁，邊界有測試。
- 寫入失敗不影響播放，也不提示，只記錯誤，有測試。
- migration v4 → v5（含 v1、v2、v3 升上來），以及全新資料庫，都有 `play_history` 和兩個索引；`RESTRICT` 有反例測試。
- 孤兒清理不刪被歷史參照的曲目。
- `navigation per window class`：三種寬度都是三個導覽項。
- 歷史頁：
  - 日分組正確，包括今天、昨天、更早、跨年；用假時鐘測。
  - 點一下是臨時播放；選單四項；只移除一筆。
  - 清除全部有確認框和提示，取消就不清。
  - 空狀態、離線案例、guideline 測試。
- 一萬筆時分頁讀取，不一次載入：測查詢的 limit，或量第一頁的耗時。
- 本機：`dart format`、`dart analyze --fatal-infos`、`flutter analyze`、`flutter test` 全綠；`install_search_play_test.dart`（Windows）通過。
- **實機**（兩平台，重播／測試插件）：
  1. 播三首，其中一首開單曲循環聽兩圈；
  2. 歷史頁有四筆，日分組正確；
  3. 點一筆會臨時播放（之後歷史再多一筆）；
  4. 移除一筆；
  5. 清除全部，先確認，再看到提示；
  6. 重開 App，歷史仍在；恢復後的第一次播放不寫歷史。
