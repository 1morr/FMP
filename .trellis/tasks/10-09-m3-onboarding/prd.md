# 首次啟動引導（M3 PR 6）

> 父任務：`.trellis/tasks/10-08-m3-sources-accounts-devtools`。技術設計在父任務 `design.md` §7.6（首次啟動引導）、§7.4（安裝確認）；ADR 0024 §決定 9（容易卡住處就地說明）、ADR 0016 §決定 7（離線空狀態）、ADR 0030。執行清單在父任務 `implement.md`「6.」。疊在 PR 5（#226，插件頁）之上。本檔只列做什麼與驗收。

## 目標

沒有可搜尋的插件時，使用者在搜尋頁就地看到官方插件清單，一次確認就裝好，不必先找到插件頁。

## 做什麼

1. 觸發：沒有任何已啟用、具 `search` 能力的插件（dev flavor 已有 `fmp-test` 就不出現）。
2. 搜尋頁的空狀態：說明一句；官方 index 的插件清單（預設全勾，可取消）；「安裝」一次確認（列出全部所選插件的能力與網域、一則共同警告）；依序安裝，失敗的列出、其他照裝；「稍後再說」後的空狀態附「前往插件頁」。
3. 離線（讀不到 index）：共用離線空狀態與「重試」。
4. 版面沿用插件頁的列與共用空狀態元件；三語言；文件。

## 不做

- 精靈式的多步驟引導；自訂 index 的插件（只列官方 index）；登入（PR 8）。

## 驗收

- [ ] widget 測試（design §7.6 的閘門）：零插件時出現、裝好後消失、全部停用時再出現、離線與重試、部分失敗、「稍後再說」；guideline 400／1000 寬。
- [ ] 驗證清單全綠（`app/AGENTS.md` § 驗證）。
- [ ] 實機（真實：官方 index 與插件 `.js`，不打音樂 API）：Android 清掉 dev 資料 → 啟動看到引導 → 全部安裝 → 搜尋 chip 是官方插件；再清一次、開飛航模式看離線狀態，關掉後按「重試」。Windows 同樣清資料後全部安裝（不停用網卡，離線只靠 widget 測試）。
