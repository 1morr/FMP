# 電台與直播介面（M3b PR 18c）

父任務：`.trellis/tasks/10-08-m3-sources-accounts-devtools`（implement.md §18、design §9.3、§9.4、§9.5、§3.3）。依據 ADR 0031 §決定 3–5、7，ADR 0024（設計系統、斷點與導覽、鍵盤與焦點、無障礙），ADR 0016 §決定 7（離線），ADR 0013 §決定 5（提示），ADR 0023（統一提示）。

PR 18 的最後一塊，前面三塊都已合併：宿主 `live` #247、B 站 `live` fmp-plugins#10、電台與直播播放 #248。資料、服務與播放核心都在，這個 PR 只做介面。父 implement.md 的「PR 18b 留下的」第 1、2 條是給這個 PR 的交接。

**版面與互動沒有定稿**：實作者照 ADR 0024 的設計系統與現有頁面（搜尋、歷史、插件、帳號、播放頁）的寫法自己定，最後在回報裡列出每個版面決定與它參照的現有元件或成熟產品慣例。下面寫的是要有什麼，不是長什麼樣子。

## 要做的

1. **導覽**：外殼加「電台」，順序是搜尋｜歷史｜電台｜設定（ADR 0031 §決定 3）。
   - 每個 window class 都要有：手機底部導覽變 4 項，寬螢幕的 rail 與抽屜同步。
   - 跟著改的地方：App 內快捷鍵、焦點三區、Android 返回鍵（若現有導覽有對應）。
2. **電台頁**（design §9.3）
   - **清單**：每列有封面、標題、主播、狀態標記。
     - 狀態有四種：開播中、未開播、查詢失敗、還沒查過。「查詢失敗」不能長得像未開播。
     - 開播中的列，顯示直播標題（`live_title`）。
     - 插件已停用或未安裝的列：保留，並標「音源已停用」或「音源未安裝」，比照現有 `pluginNameProvider` 的做法；點了以提示說明原因，不播。
   - **操作**：
     - 點一下：`playLive`。
     - 拖曳把手：排序。
     - 選單：刪除。
   - **工具列**：
     - 「以網址新增」：對話框輸入網址。三種結果以提示顯示；失敗的 `AppError` 照統一提示規則。
     - 「刷新」：呼叫手動刷新；離線時顯示離線狀態，不發請求。
   - **空清單**：說明怎麼新增，兩條路：搜尋頁的直播間模式、以網址新增。
   - **離線**：清單照常顯示存的狀態；刷新與播放失敗時，照 ADR 0016 §決定 7 顯示離線狀態。
3. **搜尋頁的直播間模式**（design §9.5）
   - 目前選的插件宣告 `live` 時，搜尋框下多一組分段鈕「曲目｜直播間」；沒宣告時不出現，而且切換插件時要退回「曲目」。
   - 直播間模式再加篩選「全部｜開播中｜未開播」，傳進 `liveSearch` 的 `status`。
   - **結果列**：封面、標題、主播、狀態、人數。
     - 點一下：`playLive`。
     - 選單：「加為電台」，結果以提示顯示。
     - 分頁載入比照曲目搜尋。
   - 錯誤、空結果、離線的狀態比照曲目搜尋。
4. **播放頁、播放列、右側「正在播放」面板的直播版**（design §9.4）
   - 讀 `playbackLiveProvider`。直播時 `QueueState.current` 是 `null`，見「PR 18b 留下的」第 1 條。
   - **要顯示**：
     - 封面、直播標題、主播、「直播中」標記；
     - 已收聽時間；
     - 人數：`live-info` 每分鐘更新；
     - 停止鈕。
   - **不顯示**：沒有進度條，也沒有上一首、下一首。
   - **其他狀態**：重連中、「直播已結束」、「查詢失敗」要看得出來，都在 `LiveInfo.phase`。
   - **佇列分頁**：照常顯示原佇列，沒有任何一列標成在播（18b 已修好，要保持）。
   - **已收聽時間**在暫停後再播、重連時從 0 重算，這是已接受的行為，見「留下的」第 2 條；不要另外做累計。
   - App 內快捷鍵在直播時的行為要合理：空白鍵是暫停（也就是停止）／播放；上一首、下一首、seek 鍵不動作。
5. **設定「網路」組**：加「電台狀態刷新間隔」一列，選項是關閉、1、3、5、10 分，預設 5 分，比照該組現有的列。
6. **Debug 頁播放狀態**：直播時顯示「直播中」與直播間（18b 的診斷已經有資料，只缺字串）。
7. **i18n**：三個語言（slang）都要補。
8. **文件**：
   - `app/AGENTS.md` § 介面、§ 電台，只寫從程式碼查不到的東西與它的閘門；
   - `.trellis/spec/app/ui/index.md` 視需要更新；
   - 父 implement.md §18 剩下的項目打勾。

## 驗收（測試）

- `navigation per window class`：四個導覽項，每個 window class 都測。
- **電台頁 widget**：
  - 四種狀態的標記；
  - 停用、未安裝插件的列；
  - 點擊會播放；排序；刪除；
  - 以網址新增的三種結果與錯誤；
  - 刷新：線上與離線兩種；
  - 空清單；
  - 離線時照常顯示存的狀態。
- **搜尋頁 widget**：
  - 只有宣告 `live` 的插件出現分段鈕；
  - 切到不宣告 `live` 的插件時退回「曲目」；
  - 篩選值傳進 `liveSearch`；
  - 「加為電台」寫入並顯示提示；
  - 點擊呼叫 `playLive`。
- **播放頁、播放列、右側面板 widget**：
  - 直播版沒有進度條，有停止鈕、人數、主播；
  - 三種 phase 的顯示；
  - 佇列分頁沒有任何一列在播。
- **快捷鍵**：直播時上一首、下一首、seek 鍵不動作。
- **設定**：刷新間隔那一列的選項，選了之後會寫入。
- **guideline 測試**：電台頁（有資料、空清單）、搜尋頁直播間模式、播放頁直播版、播放列直播版，各在寬 400 與 1000、淺色與深色下跑一次。
- 每個新閘門都做雙向變異驗證並回報。
- **驗證清單**：
  - `dart format --output=none --set-exit-if-changed lib test tool integration_test packages`
  - `dart run slang`
  - `dart analyze --fatal-infos`、`flutter analyze`
  - `flutter test`
  - 動到 lint 時跑 `packages/fmp_lints` 的 `dart test`、`dart run tool/lint_sentinel.dart`
  - 動到外殼：主對話照 `app/AGENTS.md` § 驗證跑 `toast_layering_test.dart`

## 實機（主對話做）

照父 implement.md §18 的「實測」，Android 模擬器與 Windows 都要：

- **重播**（`fmp-test`）：
  1. 在搜尋頁切到直播間模式，把一個房間加為電台；
  2. 用 `https://fmp.test/live/<roomId>` 以網址新增一個；
  3. 排序；
  4. 播放 `live-ok`，再停止，確認回到原本的佇列和位置；
  5. 播放 `live-drop`，確認提前結束後會重連；
  6. 播放 `live-ended`，確認顯示「直播已結束」；
  7. 播放 `live-broken`，確認顯示「查詢失敗」；
  8. 把間隔設成 1 分鐘：背景或最小化時，log 裡沒有狀態工作；回到前景後，到期的跑一次；飛航模式時不跑。
- **真實**（B 站匿名）：一個開播中的直播間播 30 秒，看人數更新一次；直播間模式的「未開播」篩選搜一次，驗證批次查詢的端點。
- **系統媒體控制**：
  - Android 通知：沒有進度條，沒有上一首、下一首；
  - Windows SMTC：用 `smtc_probe.ps1 -AppFilter fmp`。
