交付給任務的 PR 編號對照沒有需要更正的地方。

方法：測試名稱用 grep 在 `app/test/`、`app/integration_test/`、`app/packages/fmp_lints/test/` 確認存在；
插件端的項目在 `fmp-plugins` 的 `main`（`e25e6fd`）找 `*/test/*.test.js`、`*/checks.json`、`*/fixtures/`、
`.github/workflows/ci.yml`。PR 用 `git log -S"<測試名>"` 找第一個加入該測試的 commit，再找合併它的 merge commit，
並對照 `gh pr view` 的描述。測試檔路徑省略 `app/` 前綴；插件端的檔案前面寫 `fmp-plugins:`。
沒有實際跑 `flutter test` 或 `npm test`。
「PR」欄寫第一個加入該測試的 PR（FMP 端寫 `#`，插件端寫 `p#`）；與表上 PR 編號不同時在備註說明。
測試名稱太長時只寫開頭加 `…`（原始碼裡是跨行的字串）。
「結果」：有＝找到測試或 PR 描述；部分＝只涵蓋子項目的一部分；沒有＝找不到。
只有 PR 描述的「驗證」段能證明的（真實連線、Android 模擬器、Windows），標「實機」，並寫出是哪個 PR。
M4a 驗收的兩平台端到端（`research/m4a-acceptance.md`）尚未跑，本檔的「實機」都是各 PR 當時的驗證。

### 缺口

### 缺口

1. **探索頁的「沒有快取又離線」**：M4b 驗收第 6 步已在 Android 實機看到（首頁與探索頁都顯示離線空狀態）；探索頁的測試案例仍可補（`explore_page_test.dart` 加一條離線無快取的案例），只動測試檔，不擋驗收。
2. **停用榜單後快取列被刪**：M4b 驗收第 4 步已補：停用網易「熱歌榜」後，`cache_entries` 的 `chart:netease:hot` 立即刪掉，其餘列還在。
3. **匹配的已知誤選與未解決的評分行為**（#280、#302 的後續）：同名、時長相近、上傳者不是歌手的另一首歌（只有它一個候選時）仍會被選上，語料的 `known false matches` 守著不再變壞；候選標題包含原標題算滿分（沒有 repro）；`track_origins` 的主鍵讓後寫的蓋掉先寫的；停用插件的 `match_rank` 會留著舊值；多目標同時搜尋只有測試守，M4b 驗收第 3 步已實測（拿掉網易後沒有網易的請求）。
4. **B 站排行匿名要簽名**（p#19）：不簽名的匿名請求連三次回 -352，簽名後才通；`checks.json` 與契約重播是重播，無法證明簽名在不同日子仍被接受。健康檢查會發真實請求，若風控再變會顯示在插件健康頁，不會被測試擋。
5. **只有單元測試、沒有真實驗證的項目**：Spotify 的 `spotify.link` 短網址（p#24 的「未驗證」）；使用者自訂封面可能放在 `*.spotifycdn.com`，目前不在 `allowedHosts`；QQ 超過 1000 首的多頁行為，私人或隱藏歌單的匿名回應（p#23 的「未驗證」）；QQ `checks.json` 用的是活動歌單，下架時要換歌單重錄。
6. **備份的平台細節**（#303 的後續）：Android 上 `pickFile` 的大小上限是否生效沒有量；插件來源標記可以被偽造成官方；`browse_as_logged_in` 跟著備份走；確認框不列還原後會消失的插件。這些在實作 PR 的描述都寫成後續，沒有測試也沒有決定。
7. **Windows 實機**：M4b 驗收照 M4a 的擁有者決定，共用程式碼的步驟只在 Android 走；第 5 步（備份）兩平台都有（#303）。
8. **兩平台端到端**：見 `research/m4b-acceptance.md`（2026-10-21，FMP `main` e93a8382）。上表的「實機」欄位除標明 M4b 驗收的以外，都是各 PR 當時的驗證。
9. **歌手完全不符仍會自動選中翻唱**（M4b 驗收觀察 1）：標題（0.6）加時長（0.1）就有 0.7，超過 0.6 的門檻；實例是 QQ「那页夏天」在只搜網易時選中別人翻唱的版本（67%）。這是 PR 16 的設計（ADR 0019 §決定 5 的權重與門檻），要不要對「歌手完全不符」降分或提高門檻由擁有者決定。
10. **大歌單的搜尋量沒有提醒**（M4b 驗收觀察 3）：QQ 203 首、兩個目標約 400 次搜尋，現在沒有確認或上限，交給每插件限流；預覽頁在開始前已顯示「每首會在 n 個音源搜尋」，使用者可以先減少目標。是否需要「超過 n 首時提醒」由擁有者決定。
