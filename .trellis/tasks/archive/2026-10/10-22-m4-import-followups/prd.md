# M4 匯入的兩個後續：同文字歌手不符不自動選、大量搜尋前確認

M4b 驗收（`research/m4b-acceptance.md`「觀察與後續」第 1、3 條）留給擁有者的兩件事，擁有者 2026-10-22 回覆「按你建議」。

## 1. 同文字歌手不符時不自動選

### 背景

- `lib/core/matching/matching.dart`：權重標題 0.6、歌手 0.3、時長 0.1，門檻 0.6。標題滿分加時長滿分就是 0.7，歌手 0 也會自動選。
- 實例：QQ「那页夏天」（王俊凯）只搜網易時，自動選中網易上別人唱的同名歌（67%，歌手分 0）。
- 語料（`test/core/matching/match_corpus.dart`）刻意讓兩對歌手分 0 的仍自動選：
  - 「Spotify 給英文歌手名、網易給中文：歌手對不上，靠歌名與時長」；
  - 「Topic 頻道是英文名、原曲是中文名：歌手對不上」。
- 所以單純要求歌手分不行。能區分的是：兩邊歌手名寫成**同一種文字**還對不上，才是「另一個人唱的」的證據；不同文字（譯名、羅馬字）無從判斷，維持現狀。

### 需求

- R1：`MatchScore` 加一個「歌手衝突」判斷，`autoSelectable` 在衝突時為假。排名（`rank`）、總分、各分項不變：候選照常列出、照常排序，只是第一名不自動選，預覽頁照「匹配失敗」顯示、使用者手動挑。
- R2：衝突的條件全部成立：
  - 原曲有歌手（`artists` 非空），候選有上傳者（去裝飾後非空）；
  - 歌手分 < 0.5（`artistConflictBelow`，新常數）；
  - 至少有一位原歌手，和上傳者拆開後的某一段，**文字集合相同**。
- R3：文字集合：一個名字裡出現的字母分成 Latin、漢字、假名（平假名＋片假名）、諺文、其他；名字的文字集合是它出現過的類別（數字、標點、空白不算）。`foldText` 之後再算（繁簡、全半形已統一）。
- R4：`MatchScore` 需要知道衝突與否：評分時算好放進 `MatchScore`（新欄位，例如 `artistConflict`），`toString` 一起印。
- R5：語料加至少這幾對，並保持全綠：
  - 不該選：中文原曲、網易上另一位中文歌手唱的同名歌、時長相近（「那页夏天」的形狀，用真實公開作品）；
  - 不該選：英文原曲、上傳者是另一個英文名字、標題沒有歌手、時長相同；
  - 該選（守住譯名）：原有的兩對英中不同文字的照舊；另加日文假名歌手對中文譯名漢字（例如 `あいみょん`／`爱缪`）仍自動選。
- R6：`matching_test.dart` 加單元測試：衝突時 `autoSelectable` 假而 `total` 不變；沒有上傳者、原曲沒有歌手、歌手分 ≥ 0.5 都不算衝突。

## 2. 大量搜尋前確認

### 背景

- QQ 一張 203 首的歌單，兩個目標約 400 次搜尋；現在按「開始匹配」直接開始，節流只交給每插件限流。
- 預覽頁開始前已顯示首數與「每首會在 n 個音源搜尋」。

### 需求

- R7：按「開始匹配」時，這次要搜的次數＝（要搜的首數，不含沿用的）×（目標數）。超過 200（`largeSearchThreshold`，新常數，放在 `external_import.dart` 或預覽頁，擇一並說明）時先跳確認框；否則照舊直接開始。
- R8：確認框：標題「要搜尋約 N 次」一類、內文說明會花一些時間、可以先減少匹配目標；按鈕「取消」「開始」。取消＝什麼都不做，留在預覽頁。照 `lib/ui/plugins/plugin_dialogs.dart` 既有確認框的寫法與 ADR 0024 的版面。
- R9：字串進 slang（`app/lib/i18n/` 的 zh-Hant、zh-Hans、en 都要有），`dart run slang` 產生。
- R10：widget 測試：超過門檻跳確認框、取消不開始、確認後開始；未超過不跳。
