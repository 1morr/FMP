# M5 舊資料匯入

> 擁有者核准 prd／design／implement 之前不開工（ADR 0026 §決定 1）。技術決定在 `design.md`，PR 順序在 `implement.md`。
> 已核准（2026-10-23，擁有者「照建議」）：`design.md` §11 的確認清單（12 條）與 ADR 0010、0012、0029、0034 的補充與更正（design §10）。

## 目標

新 App 第一次啟動時，自動把舊版的歌單、曲目、播放歷史、佇列、電台、設定、帳號與登入憑證搬進新資料庫；也能從設定頁匯入舊版的 JSON 備份檔（`../09-26-fmp-rewrite/milestones.md` § M5，ADR 0010 §決定 4）。做完後擁有者以 dev flavor 加真實資料副本開始日常試用。

## 背景

- 範圍與驗收的來源：`milestones.md` § M5；行為以 ADR 0010 §決定 4 為主，另見 ADR 0008（App 身分沿用）、0012 §3、§6（憑證、以登入身分瀏覽）、0014 §決定 8 與 0030 §12（提示安裝音源）、0017 §決定 6（刷新間隔照舊值）、0026 §決定 2（各里程碑補自己那張表的匯入）、0029（憑證形狀）、0034（還原的換檔與重啟）。
- 先前里程碑留給 M5 的對照：M2 design §3.6（佇列、歷史）、M3 design §3.4（帳號、憑證、電台、Mix 佇列）、M4 design §3.4（歌單、排行設定）；都已併入 `design.md` §5。
- 研究（2026-10-22）：
  - `research/legacy-sources.md`：舊 Isar 的 11 個 collection、鍵格式、檔案位置、JSON 備份 v1–v5、設定與舊 migration、憑證的鍵與形狀、Isar 的開啟行為；
  - `research/target-schema.md`：新版 22 張表、寫入 API、資料目錄、啟動流程、ADR 0034 的換檔機制、dev 入口、lint；
  - `research/secure-storage-compat.md`：`flutter_secure_storage` 10.3.1 與 11.2.0 在 Android、Windows 的相容性；
  - `research/isar-copy-spike.md`：以舊模型開擁有者舊庫的副本（原檔不變、各 collection 的筆數、鎖檔後綴）；
  - `research/android-credentials-compat.md`：Android 上 11.2.0 讀 10.3.1 寫的資料的實測（一次性測試 App）。

## 擁有者的決定

先前已定、在 M5 沿用的：

1. **舊資料庫、登入憑證、已下載檔、舊備份檔全部自動遷移**（`docs/audit/questions.md` A3）；下載檔的登記在 M6（ADR 0026 §決定 2 的表）。
2. **永不自動刪舊檔**；匯入成功後設定頁提供「刪除舊版資料」（ADR 0010 §決定 4）。M5 規劃時建議移到 M9：M6–M8 還要從舊資料庫補匯（design §1.2、§11 第 7 條）。
3. **migration 不得改寫使用者設定過的值**；舊版被強制改過的設定照現值匯入（ADR 0010 §決定 3、4）。
4. **「以登入身分瀏覽」以舊開關值作為使用者設定**（ADR 0012 §決定 6）。
5. **實機驗證：Android 每個使用者看得到的 PR，Windows 只在改到平台各自實作時與里程碑驗收**（ADR 0027 §決定 3 的 2026-10-13 修訂）。
6. **M4b 起擁有者授權主對話自己驗收**（2026-10-22「你試完通過就可以了」）；M5 的第二個驗收項（擁有者開始日常試用）由擁有者自己勾。

7. **M5 規劃的 12 條（`design.md` §11）全部照建議**（2026-10-23）：包括「刪除舊版資料」移到 M9、設定頁的匯入是取代並保留插件與登入、Windows 驗收匯入真實憑證（接受 B 站換 cookie 後另一邊登出一次）、搜尋歷史另開 issue。

## 範圍

明細見 `design.md` §1；PR 見 `implement.md`。

- `lib/legacy_import/`：舊 Isar 的模型與讀取器（先複製再開副本）、舊 JSON 備份的讀取器、轉換器（舊資料 → 新資料的匯入包）。
- `lib/data/`：匯入包寫進暫存庫（保留原始時間）、驗證（筆數、抽樣、外鍵、完整性）、換上；匯入紀錄表 `legacy_imports`（schema v19）。
- `lib/platform/`：找舊資料的位置；唯讀讀出舊憑證（Windows 直接解 DPAPI 檔，Android 以 11.2.0 的舊設定實例）。
- 啟動流程：首次啟動偵測、進度畫面、失敗頁（重試、匯出診斷、以空白資料啟動）、成功後的結果對話框；`DatabaseErrorApp` 補重試與匯出診斷。
- 設定頁「備份與還原」區：「從舊版匯入…」（舊版資料庫或舊版備份檔）：取代音樂庫與舊版有的設定，保留插件、插件設定與這台的登入（design §6.3）。
- dev 入口 `--fmp-legacy-dir=<資料夾>`：dev flavor 讀資料副本。
- ADR 0010、0012、0029、0034 的補充與更正（design §10）。

## 不在範圍

- 舊下載紀錄與已下載檔的登記（M6）；舊歌詞配對、歌詞設定、AI 端點與 API key（M7）；托盤、快捷鍵、開機自啟等桌面設定（M8）。這些仍留在舊資料庫與舊憑證裡，由各自的里程碑以同一個讀取器補匯（design §1.2）。
- 新版沒有落腳處的舊設定與功能（主色、字型、每音源串流優先、快取上限、首頁排行的順序與停用、搜尋歷史等）：不匯入，在結果裡列出（design §1.3，§11 第 2、3 條）。
- 自動安裝音源插件：匯入後沿用既有的首次引導（ADR 0030 §12）。
- 「刪除舊版資料」：移到 M9（design §7.4）。
- 從 v1.11.0 的實際升級（M9 的驗收，ADR 0022）。

## 驗收

（`milestones.md` § M5；證據寫在 `research/m5-acceptance.md`）

- [x] 擁有者開始以 dev flavor＋真實資料副本日常試用（2026-10-24）。
- [x] ADR 0010 §如何確認 與本任務新閘門的測試（design §9）：讀取器不寫舊檔、轉換器的對照、暫存庫驗證失敗時不換上、匯入中途失敗不留半套資料、設定頁的取代保留插件與登入、`lib/legacy_import/` 只被 `lib/main.dart` 引用、prod 不讀 `--fmp-legacy-dir`。
