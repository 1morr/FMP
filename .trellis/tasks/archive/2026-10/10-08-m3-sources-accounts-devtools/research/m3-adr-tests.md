方法：測試名稱用 grep 在 `app/test/`、`app/integration_test/`、`app/packages/fmp_lints/test/` 確認存在；
插件端的項目（判定表、錯誤對應、契約 fixture、CI）在 `fmp-plugins` 的 `main`（`6fe837c`）找
`*/test/*.test.js`、`*/checks.json`、`*/fixtures/`、`.github/workflows/ci.yml`。
PR 用 `git log -S"<測試名>"` 找第一個加入該測試的 commit，再找合併它的 merge commit，
並對照 `gh pr view` 的描述。測試檔路徑省略 `app/` 前綴；插件端的檔案前面寫 `fmp-plugins:`。
沒有實際跑 `flutter test` 或 `npm test`。
「PR」欄寫第一個加入該測試的 PR（FMP 端寫 `#`，插件端寫 `p#`）；與表上 PR 編號不同時在備註說明。
「結果」：有＝找到測試或 PR 描述；部分＝只涵蓋子項目的一部分；沒有＝找不到。

### 需要主對話決定

1. **0025「重設：成功時已下載的檔案仍在」沒有測試**：`lib/` 沒有下載功能（下載在 M6，`app/AGENTS.md` 也寫「M6 的下載通知另行處理」），`AppDataReset` 只處理資料庫、憑證、WebView、快取，不碰其他目錄。現有的 `leaves an empty database, no credentials, and keeps logs and backups` 守的是 log 與備份目錄還在。建議：接受缺口，理由是 M3b 沒有可下載的檔案；M6 加下載時在 `data_reset_test.dart` 補一條「重設後下載目錄的檔案還在」，並在 ADR 0025 §如何確認那一行加註「M6 起生效」（一行更正，不是改決定）。不建議現在寫替代測試：沒有下載功能就寫不出失效條件。
2. **ADR 0028 §如何確認寫的測試檔名與實際不符**：它寫 `script_source_plugin_test.dart` 守「宣告 `live`、`mix`、`multiPart`、`trackDetail` 而沒有匯出時拒載、多出的欄位拒收」，但該檔沒有這四個能力的案例，實際在 `live_capability_test.dart`、`mix_capability_test.dart`、`multi_part_capability_test.dart`、`track_detail_capability_test.dart` 四個檔。測試本身都在，只是 ADR 的檔名過時。建議：ADR 0028 加一行更正，把檔名改成四個 `*_capability_test.dart`（ADR 規則：事實錯誤只做一行更正）。
3. **Mix 修剪沒有實機證據**：#251 實機只播到約 56 首，沒到 100。單元測試有 100／101／105 的邊界、目前這首身分不變、非 Mix 不修剪。建議：接受，理由是邏輯在 `QueueModel`，邊界已測；不為這個延長實機。
4. **多 P 與三音源詳細的 App 實機還沒有紀錄**：p#12 與 FMP #253 都把它留到合併後，屬於 M3b 驗收步驟 7、8。這兩項不在 ADR 表上，所以沒計入統計；請確認 `m3b-acceptance.md` 會涵蓋。
5. **電台頁「離線時按手動刷新」的提示行**：#250 記下實機沒看到，只有 `radio_page_test.dart` 的 `offline, nothing is sent and the page says the status is the last known one` 守。建議：接受，M3b 驗收步驟 5 的「背景與離線不跑」順便按一次手動刷新。
6. **PR 16c 未做，`requiresLogin` 沒有官方插件的真實案例**：ADR 0028 的略過邏輯有測試，但三個官方插件的 `checks.json` 目前都沒有 `requiresLogin` 案例（只有 `login`）。`implement.md` 的 PR 16 清單 16c 仍是未勾。建議：確認 `milestones.md` 的 M3b 打勾是否允許帶著 16c（需要擁有者登入），或另開後續任務；這不影響上表任何一列的結果。
