# M1 播放核心與照稿頁面

細化自 roadmap〈M1 播放核心與照稿頁面〉（2026-11-14 開工）。決定的來源是 brief；本檔與 brief 衝突時以 brief 為準，要推翻先問擁有者。

## 目標

只用 B 站做完播放核心：佇列、臨時播放、播放模式、持久化、串流過期重解析、預載、失敗處理、背景播放與系統媒體控制；並照 `docs/design/` 的定稿做出 App 外殼、首頁、搜尋頁、迷你播放器、播放頁、佇列頁與設定頁的外觀與播放。M1 結束時，四個平台上能用照稿的畫面搜尋 B 站、排佇列、臨時播放（含一組分 P），背景與系統媒體控制可用，播放核心與音源無關，M1.5 只要加插件。

## 範圍

### 做

- 插件能力（ADR 0039）：`search` 帶排序、`listParts`、`charts`、`trackInfo`，只做 bilibili；每個的介面由實作的票寫回 ADR 0039〈各插件能力的介面〉。
- 播放核心：佇列、臨時播放（含一組分 P 當一首）、隨機與循環、佇列與進度跨重啟保存、串流過期前重新解析、預載下一首、失敗處理（重新解析一次 → 跳下一首 → 連續 3 首停止並提示）、看門狗。
- 音訊後端介面加 seek 與預載下一首（`mattpocock-skills:codebase-design`）。
- 背景播放與系統媒體控制：Android、iOS、macOS 用 audio_service，Windows 用 runner 裡自己接的 SMTC（brief §6；2026-11-19 擁有者同意，原本是 smtc_windows）。
- 照稿切版：設計系統（改用 `material_ui`，事實 T1）、玻璃元件三級、App 外殼三種寬度、迷你播放器與播放膠囊、Toast、首頁（繼續聽、近期熱門）、搜尋頁、佇列頁、播放頁（封面、佇列、曲目資訊）、設定頁（外觀、臨時播放倒退秒數）。
- 依賴規則補兩條：`platform/` 以外不得用 `defaultTargetPlatform`；`domain/` 不得 import Flutter。
- ARCHITECTURE〈快取〉照做（開工時已寫入）。
- M0 留下的：插件宿主的兩個競態、插件 id 與曲目 id 成對的型別、未捕捉的錯誤寫 log、mpv 設定與 log 分類、`audio_session`、開資料庫失敗的呈現、資料完整性測試骨架、WBI 的 fixture 比對、macOS 點下到出聲慢的原因。

### 不做

- youtube、netease 插件，依音源限流，串流與圖片網址的網域檢查（M1.5）。
- 登入、存取等級、音質選擇、試聽、播放失敗先降一級音質（M2）。
- 音樂庫、歌單詳情、加入歌單、匯入歌單、遠端寫入（M3）；歌詞（M4）；插件頁、設定的儲存空間、匯出診斷、關於（M5）。
- 磁碟音訊快取（brief §9）。
- 升級 Flutter 到 3.50（roadmap〈不排里程碑〉）。

## 共同規則

- **平台與實跑**（2026-11-18 改，擁有者同意）：完整閘門每張票都跑四平台（winpc 恢復前用 `--skip-windows`，`docs/decisions.md`）。實跑看改到哪一層：只改共用的 Dart（佇列與播放規則、提示文字、共用畫面）時，macOS 加一個手機平台（iOS 或 Android）；改到平台各自不同的那層（音訊後端與播放器設定、視窗外框與紅綠燈、檔案與資料目錄、背景播放與系統媒體控制、原生程式碼）時，受影響的每個平台；版面依寬度不同的畫面，三種寬度照〈照稿〉截圖。票面寫「四平台實跑」的照這條縮小；拿不準屬哪一層時當成平台那層。M1 驗收（票 20）仍四平台實跑。方式照 `docs/development.md`〈平台〉，以讀回的畫面為準；實跑先用〈實跑驅動〉，不動擁有者的游標，真滑鼠只用在它列的例外。
- **閘門**：每張票合併前跑 `dart run tool/check.dart` 完整版。M0 的 integration_test 換畫面後要跟著改，不能刪掉不補。
- **照稿**：照 `docs/design/` 的定稿與 `DESIGN.md` 切版，三種寬度、深淺色都做；偏離先問擁有者。UI 票附截圖或讀回的畫面文字，和設計稿同一個狀態並排比對。
- **還沒有的功能不出現入口**（2026-11-14 擁有者同意）：入口依插件能力與現有功能出現，不畫佔位。例如沒有插件宣告 `lyrics`，播放頁手機只有「佇列 ← 封面」兩個畫面；首頁沒有「最近更新的匯入歌單」；選單沒有「加入歌單」；設定只有已實作的分類。之後的里程碑把入口加回去。
- **插件能力**：新增插件能力時加 `PluginCapability` 的值、在契約測試的 `checkContract` 補契約、錄 fixture、加一條 `live` 冒煙測試，並在 ADR 0039〈各插件能力的介面〉補一小節（函式名、輸入、輸出、manifest 多的欄位）。
- **WBI**：第一張錄到帶 `wts`、`w_rid` 請求的票，先讓契約測試重播比對網址時忽略這兩個參數（M0 票 09 的 Comments），再錄 fixture。
- **模組介面**：佇列、臨時播放、音訊後端的介面用 `mattpocock-skills:codebase-design`；佇列與播放模式的規則是純 Dart，放 `domain/` 或 `playback/`，單元測試逐條對到 brief §6。
- **資料庫**：改 schema 照 ARCHITECTURE〈測試策略〉；平行的票撞到 migration 編號照 `AGENTS.md`〈每個 session 的流程〉第 7 步。
- **依賴**：加依賴時查 pub.dev 當前 stable，版本寫進 ARCHITECTURE〈主要依賴〉。
- **字串**：新字串同票補齊 zh-TW、zh-CN、en。
- **命名**：用 `GLOSSARY.md` 的詞；缺的詞照 `AGENTS.md`〈擁有者確認〉補。
- **事實**：用到標【待重驗】的事實時當場重驗，驗過拿掉標記，對不上就改寫並附來源。
- **聯網**：測試零聯網。實跑與 `live` 測試用匿名請求，每次只搜一次、播一首（事實 F2）；fixture 照 `AGENTS.md`〈公開 repo〉遮蔽。
- **擁有者在場**：07 開工前、04 與 12 的量測結果、20 的使用者試要擁有者，做到那一步停下等。

## 驗收

### Agent 驗

- [ ] 四個平台上，用照稿的搜尋頁搜尋 B 站並播放一首，也臨時播放一組分 P，整組播完回到佇列原本那首；M1 主要流程的 integration_test 四平台通過。
- [ ] 臨時播放、隨機與循環的組合照 brief §6 運作：單元測試逐條對到 brief §6 的每一點，四平台實跑讀回佇列頁。
- [ ] 佇列與進度跨重啟保存，重啟後停在原本那首、不自動播放；臨時播放不保留。
- [ ] 失敗處理：重新解析一次、跳下一首、連續 3 首失敗停止並提示，有測試；串流過期前重新解析，有測試。
- [ ] 預載後「按下一首到出聲」在四個平台達到擁有者在票 12 定的目標，數字寫進 `docs/research/`。
- [ ] 背景播放與系統媒體控制：四個平台上，App 在背景（手機鎖屏或切走、桌面最小化）時繼續播放，系統的播放、暫停、上一首、下一首有作用，Now Playing 顯示曲名、作者、封面（模擬器驗不到的記下來）。
- [ ] 外殼、首頁、搜尋頁、迷你播放器、播放頁、佇列頁、設定頁在三種寬度、深淺色的截圖和設計稿對得上。
- [ ] ADR 0039〈各插件能力的介面〉有 `search`（排序）、`listParts`、`charts`、`trackInfo`；ARCHITECTURE〈依賴規則〉有兩條新規則，依賴規則測試做了雙向變異驗證。
- [ ] 在乾淨的 checkout 跑 `dart run tool/check.dart` 完整版綠燈。

### 使用者試

啟動方式：每個平台照 `docs/development.md`〈平台〉的「開 App」指令開 dev 版。

- [ ] 四個平台各親耳聽：搜尋一首 B 站、播放、下一首、臨時播放一組分 P 再回到佇列，聽得出倒退秒數；切歌快不快。
- [ ] 背景播放：手機鎖屏、切到別的 App，桌面最小化，聲音不斷。
- [ ] 系統媒體控制：Android 通知與鎖屏、iOS 控制中心與鎖屏（中斷與 Now Playing 模擬器驗不到，事實 I2、I5；沒有實機就記為沒試）、macOS 控制中心與媒體鍵、Windows 的媒體浮層與媒體鍵。
- [ ] 照稿頁面的手感：導覽、拖動排序佇列、播放頁左右滑、桌面右鍵選單、玻璃效果三個選項的外觀與流暢度。
