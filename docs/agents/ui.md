# UI：設計稿與實作

`AGENTS.md`〈UI〉指到這裡：排 roadmap、做對比版、做會新增畫面或改版面的票之前照這份做。

- 照 `docs/design/` 的定稿實作，要偏離先問擁有者。定稿之後才新增或大改的畫面，在那張票的第一步用 `impeccable:impeccable` 出設計，擁有者確認後才實作。
- 定稿是 roadmap 的 `D 設計稿` 階段產出的靜態 HTML；之後的設計稿也放 `docs/design/`。有爭議的地方給 A／B 兩個方案；只改文案、修 bug、不動版面的票不用出設計。
- 做對比版：每一版在自己的 worktree 做，只讀 brief 與 `docs/design/DESIGN.md`，別的版本的設計稿留到擁有者比較時才打開。
- 動態：做會新增畫面或改版面的票時，列出畫面上每個會變化的狀態（出現／消失、展開、換內容、選取），對照 `DESIGN.md` §3.4〈狀態變化對照〉；表上沒有的照它的預設做，在票上記 `決定：…（Agent 定）`，預設不適用就問擁有者。有動畫的改動要有一條在動畫中途檢查的 widget 測試，或一張動畫中途的實跑截圖；靜態截圖看不出「突然出現」。
