# 事實：平台

查證過的外部事實，一條一個編號，編號不重用。可信度標記與 `legacy:`、`archive:` 的意思見 [brief〈事實索引〉](../design-brief.md)。

## 事實

### Android

- **A1** App 自動備份會還原 shared preferences，但 Keystore 金鑰不會跟著還原，secure storage 解不開還原的憑證；設 `allowBackup="false"`。出處：`legacy:android/app/src/main/AndroidManifest.xml:26-31`（issue #35）。可信度：舊版程式碼。
- **A2** `MANAGE_EXTERNAL_STORAGE` 加裸路徑不能上 Google Play；`permission_handler_windows` 一註冊就訂閱位置事件，Windows 會顯示 App 正在使用位置。出處：`legacy:lib/services/platform/storage_permission_service.dart:18-24`。可信度：舊版程式碼。
- **A3** AGP 9 下，`package_info_plus` 9.0.1 需要 `android.builtInKotlin=false`；`file_picker` 11.0.3 要手動套 KGP。出處：`legacy:android/gradle.properties:3-6`、`legacy:android/build.gradle.kts:18-26`。可信度：舊版程式碼。
- **A4** AGP 9 移除了 `proguard-android.txt`，`flutter_inappwebview` 6.1.5 帶進來的 `flutter_inappwebview_android` 1.1.3 在 `build.gradle` 還在用：AGP 9.1.0 下 debug 與 release 都在 Gradle 設定階段失敗（`getDefaultProguardFile('proguard-android.txt')` is no longer supported）。App 的 `gradle.properties` 加暫時旗標 `android.r8.proguardAndroidTxt.disallowed=false` 後，debug、release（R8）都建得過、開得了網頁。上游 https://github.com/pichillilorenzo/flutter_inappwebview/issues/2852 仍開著（2026-11-11）。出處：M0 票 04（`scripts/experiments/inappwebview/`）；`legacy:android/gradle.properties:9-12`。可信度：2026-11-11 實測。
- **A5**【待重驗】targetSdk 36 在 Android 16 預設開 predictive back：從通知等入口開啟的 task 按返回鍵會被 finish；要覆寫 `setFrameworkHandlesBack(true)` 與 `popSystemNavigator`。出處：commit `b2421e88`。可信度：上一版文件。
- **A6** `audio_service` 0.18.19 在 Android 把真正的媒體鍵 `KEYCODE_MEDIA_PLAY`、`KEYCODE_MEDIA_PAUSE` 和 `PLAY_PAUSE`、耳機鍵一樣轉成 `click(MediaButton.media)`，`BaseAudioHandler.click` 依目前的 `playing` 切換，所以暫停時再按暫停鍵會開始播放；通知與鎖屏上的播放、暫停鈕改用內部的 bypass 鍵碼，照常是 play、pause。Dart 端分不出是哪個鍵。出處：audio_service 0.18.19 `android/src/main/java/com/ryanheise/audioservice/AudioService.java:944-1000`；上一版 commit `fb75a020`。可信度：2026-11-19 讀原始碼，沒有在裝置上按實體鍵。
- **A7**【待重驗】來電中斷後要在背景續播，會撞上 Android 12+ 的前景服務限制，中斷期間要回報 `playing` 加 `buffering`；`AUDIOFOCUS_LOSS` 不會送結束事件。出處：commits `a737e41c`、`2bfce093`。可信度：上一版文件。

### Windows

- **W1** Material `Slider` 與 hover 時的 `Tooltip` 會弄壞 Windows 的無障礙樹，之後 Narrator 讀不到內容（flutter/flutter#182444，未修）；`Slider` 要包 `Overlay.wrap`。出處：`legacy:lib/ui/widgets/controls/scoped_slider.dart`、`docs/legacy/troubleshooting.md`。可信度：舊版程式碼。
- **W2** `runApp()` 之前的例外會變成「雙擊後什麼都沒發生」，要 try/catch 並顯示錯誤畫面。出處：`legacy:lib/main.dart:46-62`（issue #37）。可信度：舊版程式碼。
- **W3** `media_kit_libs_windows_audio` 1.0.9 帶的是 2023-09-24 的 libmpv（mpv 0.36、FFmpeg 6.0），pub 上沒有更新版（2026-11-06 查）；同一條串流 Android 能播、Windows 不能時先懷疑它。出處：`docs/legacy/troubleshooting.md`、`docs/research/audio-webview-2026-11.md`。可信度：舊版文件加 2026-11-06 研究。
- **W4** media_kit 的 `errorController` 不轉發 `ao` 開頭的錯誤（音訊裝置失敗），要另聽 log；長度為零的串流不報錯、一直 buffering，要有看門狗。出處：`legacy:lib/services/audio/media_kit_audio_service.dart:384-392`、`legacy:lib/services/audio/buffer_starvation_watchdog.dart:11-14`。可信度：舊版程式碼。
- **W5** media_kit 在 Windows 上同時 dispose 多個 player 會原生 crash（media-kit #1472）。出處：`docs/research/audio-webview-2026-11.md`。可信度：2026-11-06 研究。
- **W6** `smtc_windows` 1.1.0 的限制（新版不用它，事實 W7；這裡留著給自己接 SMTC 時參考）：按鈕事件只有 play、pause、next、previous、stop 這類（`PressedButton`），沒有 `PlaybackPositionChangeRequested`，所以收不到拖進度；`update_metadata` 只設非 null 的欄位、不清掉舊的，換歌時要先 `ClearAll`；封面用 `RandomAccessStreamReference::CreateFromUri`。【待重驗】上一版文件另記兩點，這次只讀了原始碼、沒在 Windows 上試：時間軸不會自己前進，要每約 5 秒重推位置；讀不到 `file:///` 的封面，要給 https。出處：smtc_windows 1.1.0 原始碼 `lib/src/enums/button_event.dart`、`rust/src/internal/smtc_internal.rs:51-83`；`legacy:lib/services/audio/now_playing_publisher.dart:283-284`。可信度：前半 2026-11-19 讀原始碼，【待重驗】兩點是上一版文件。
- **W7** `smtc_windows` 和 fjs 不能同時用：smtc_windows 最新的 1.1.0（2025-08-18，上游之後沒有改動）以 flutter_rust_bridge 2.11.1 產生，Rust 端釘 `=2.11.1`、Dart 端 `^2.11.1`，沒有用 2.13 的版本；fjs 3.3.2 的 Dart 與 Rust 端都釘 2.13.0，pub 因此解出 Dart 端 2.13.0。FRB 2.13.0 的 `initImpl` 先比對產生碼的版本與執行時的版本，不同而 `forceSameCodegenVersion`（預設 `true`）時丟 `StateError`；smtc_windows 的 `SMTCWindows.initialize()` 用預設值呼叫 `RustLib.init()`，所以在這個組合下一初始化就失敗。FRB 文件的升級方式只有重新產生、讓兩端同版。另外 smtc_windows 沒設預先編好的二進位（沒有 `cargokit.yaml`），每次建置都從原始碼編 Rust，Windows 要裝 rustup（README 的 Requirements）；fjs 有設，從 GitHub release 下載。新版因此在 Windows runner 自己用 C++ 接 SMTC（brief §6）。出處：smtc_windows 1.1.0 `rust/Cargo.toml:10`、`lib/src/rust/frb_generated.dart:26-37,74`、`lib/src/smtc_windows_base.dart`（`initialize`）、README；fjs 3.3.2 `pubspec.yaml:24`、`libfjs/Cargo.toml:18`、`cargokit.yaml`；flutter_rust_bridge 2.13.0 `lib/src/main_components/entrypoint.dart:44-53,108-128`；https://cjycode.com/flutter_rust_bridge/guides/miscellaneous/upgrade/regular ；pub.dev 兩個套件的版本清單。可信度：2026-11-19 讀原始碼與 pub.dev，沒在 Windows 上跑。
- **W8** `flutter_inappwebview_windows` 0.6.0（6.1.5 帶進來的）在 VS 2026（MSVC 14.51.36231）不加設定時，插件編譯報 `error C2338`（STL1011：`<experimental/coroutine>` 已棄用），要在 App 的 `windows/CMakeLists.txt` 對 `flutter_inappwebview_windows_plugin` 加 `_SILENCE_EXPERIMENTAL_COROUTINE_DEPRECATION_WARNINGS`。`/FS`（防多個編譯行程同時寫同一個 PDB 的 C1041）沒重現出需要：只加 define 的乾淨建置 3 次成功、沒出現 C1041，插件的 CMake 也沒開 `/MP`；留著當保險（舊版的註解說它在 VS 2022 不起作用，這點沒實測）。繁中 Windows（cp950）下插件只報 C4819 警告：插件用自己的標準設定、刻意不開 `/WX`，所以不需要 `/utf-8`（舊版 `windows/` 也沒加）。上游 PR https://github.com/pichillilorenzo/flutter_inappwebview/pull/2869 仍開著（2026-11-11）。出處：M0 票 04（`scripts/experiments/inappwebview/` 的 README〈W8〉，13 次建置的結果）；`flutter_inappwebview_windows-0.6.0/windows/CMakeLists.txt`；`legacy:windows/CMakeLists.txt:60-73`。可信度：2026-11-11 在 `winpc` 實測。
- **W9**【待重驗】`flutter_secure_storage_windows` 把所有鍵值用 DPAPI 存成單一 `flutter_secure_storage.dat`，解不開或 JSON 壞掉就整個刪掉；鍵名只能用小寫英數、`.`、`-`。出處：`archive:docs/adr/0029` §決定 5 更正。可信度：上一版文件。
- **W10**【待重驗】`desktop_multi_window` 的子視窗 engine 不能註冊 `tray_manager`、`hotkey_manager`、`window_manager`（它們用全域 static channel）。出處：`docs/legacy/audit/platforms.md` §3.7。可信度：上一版文件。
- **W11** media_kit 1.2.6 在 Windows：`Player` 還在播時關掉 App 視窗，整個行程崩潰。事件記錄是 `fmp.exe` 在 `flutter_windows.dll` 出 `0xc0000409`，stderr 有 `runtime_entry.cc: 5363: error: GetFfiCallbackMetadata called after shutdown`：Dart VM 關掉後，libmpv 的執行緒還在呼叫 media_kit 的 FFI callback。修法是 App 要結束時先 `dispose` player：`AppLifecycleListener.onExitRequested`，Windows 關視窗會經過它。修正後同樣的步驟正常結束，沒有事件記錄。出處：M0 票 11（`app/lib/app/audio_backend_lifecycle.dart`、`app/test/app/audio_backend_exit_test.dart`；重現：播一首後關視窗，當時用 `tool/winpc/shot.ps1 -Type lemon -Click 200,262`；這兩個會移游標的旗標票 08b 已刪，重驗時另寫播放後關視窗的步驟）。可信度：2026-11-12 `winpc` 實測，修正前後各一次。
- **W12** Windows 11 沒有原生標題列的視窗要出 Snap Layouts（滑鼠停在最大化鈕上跳出的排列選單），最大化鈕那一塊的 `WM_NCHITTEST` 要回 `HTMAXBUTTON`（Microsoft 文件）。Flutter 的畫面是蓋滿客戶區的子視窗 `FLUTTERVIEW`，滑鼠訊息先到它：把它的 window procedure 換掉，在最大化鈕與頂端拉邊緣的那條回 `HTTRANSPARENT`，訊息就落到主視窗，主視窗回 `HTMAXBUTTON`、`HTTOP`，Snap Layouts 與頂端拉邊緣都出得來；之後最大化鈕的滑鼠進出、按下、放開改以 `WM_NCMOUSEMOVE`、`WM_NCMOUSELEAVE`（要 `TrackMouseEvent` 帶 `TME_NONCLIENT`）、`WM_NCLBUTTONDOWN`／`UP` 送到主視窗，Flutter 收不到，hover 與按下的樣子要由原生端告訴 Dart；`WM_NCLBUTTONDOWN` 不能交給 `DefWindowProc`，否則它會照舊式標題列鈕處理。`WM_NCCALCSIZE` 先讓 `DefWindowProc` 算標準外框、再把頂端改回原值，就拿掉標題列與頂框、保留左右下的拉邊緣（Windows Terminal 的做法）；最大化時視窗會超出螢幕一個拉邊緣寬（`SM_CYSIZEFRAME` 加 `SM_CXPADDEDBORDER`），頂端要再內縮這麼多。Windows 11 的 1px 外框四邊都還在。拖動視窗：Flutter 拖動手勢開始時 `ReleaseCapture` 再對主視窗送 `WM_NCLBUTTONDOWN`（`HTCAPTION`），系統接手拖動、拖到螢幕邊緣會貼齊，拖完 Flutter 照常收得到點擊。Flutter 3.47.5 的 Windows 引擎不處理 `WM_LBUTTONDBLCLK`、視窗類別也沒有 `CS_DBLCLKS`，雙擊由 Flutter 的手勢辨認。另一個行程對 `FLUTTERVIEW` 送 `WM_NCHITTEST` 當檢查不可靠：第一次量讀到 `HTCLIENT`（那次 App 不在前景），之後三次讀到 `HTTRANSPARENT`，原因沒查；以真的滑鼠驗為準。出處：https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/ui/apply-snap-layout-menu ；https://github.com/microsoft/terminal/blob/main/src/cascadia/WindowsTerminal/NonClientIslandWindow.cpp ；https://github.com/luoluoqixi/flutter_windows11_snap_layouts_examples ；M1 票 05b（`app/windows/runner/window_frame.cpp`）。可信度：2026-11-17 在 `winpc`（Windows 11、150% 縮放、Flutter 3.47.5）以 SendInput 的真實滑鼠實測。
- **W13** mpv 0.36（`media_kit_libs_windows_audio` 1.0.9 帶的那版，事實 W3）的 `cplayer` 在 error 級寫的訊息不一定代表播不下去：會讓這首播不了的是 `Failed to recognize file format.`（loadfile.c）、`Could not open/initialize audio device -> no sound.`（audio.c）與 fatal 級的 `No video or audio streams selected.`（loadfile.c）；其餘 error 聲音照常，例如 `Cannot seek in this stream.`（playloop.c）、`Track %d is already selected.`、`Disabling stream recording.`、`Error reinitializing audio.`，以及指令與 overlay 的參數錯誤（command.c）。media_kit 1.2.6 把所有 `cplayer` 的 error 都轉發到 `stream.error`（事實 K26），不能照單全收。出處：https://github.com/mpv-player/mpv/blob/v0.36.0/player/loadfile.c （`MP_ERR`／`MP_FATAL`，約 1750、1900 行）、`player/audio.c`（約 481、789 行）、`player/playloop.c`（約 348 行）、`player/command.c`。可信度：2026-11-18 讀 v0.36.0 原始碼。

- **M1**【待重驗】ad-hoc 簽章下，`flutter_secure_storage` 的預設設定回 `-34018`；加了 `keychain-access-groups` 卻沒有 provisioning profile，App 一啟動就被 AMFI 殺掉。`usesDataProtectionKeychain: false` 可用，但 `readAll` 回 `-50`。出處：`archive:docs/adr/0036` §決定 3。可信度：上一版文件。
