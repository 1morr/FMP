# 0026 — 里程碑與切換：九個縱向切片里程碑、里程碑任務底下開 PR 子任務、同機並量與兩週試用的放行條件

- 狀態：已採納
- 日期：2026-09-28
- 影響範圍：`fmp-rewrite` 的任務結構、`.trellis/tasks/09-26-fmp-rewrite/milestones.md`、各平台任務的時程與測試環境、切換 PR 的放行條件

## 背景

ADR 0008 定了高層策略：
- 同 repo 的 `app/`；
- 主幹開發；
- 第一個里程碑是 tracer bullet；
- 切換條件是保留的功能跑通、效能不低於基準、舊資料遷移驗證過。

里程碑本身留到所有設計定案後才拆。

現況（`.trellis/tasks/archive/2026-09/09-28-design-milestones/research/`，已抽查）：
- 沒有任何里程碑清單。8 份 ADR 只寫「第一個里程碑」「加入下載的里程碑」「切換前」這類描述。
- 第一個里程碑已累積 10 份 ADR 的必要驗證（`phase2-plan.md` §7），另有 §8 的延後實測、§9 的待排項目。
- ADR 0008 §決定 5 與 parent prd 的完成定義都寫「`features.md` 中勾『保留』」，但 `features.md` 沒有勾選欄；實際勾選在 `questions.md`（E1–E17 保留）。
- parent prd 同時要求「每個里程碑是一個 child task」與「每個 child task 一個可 review 的 PR」，第一個里程碑一個 PR 裝不下。
- Android 上新 App 與舊 App 同身分，是覆蓋升級，不能降版回舊版。

擁有者 2026-09-28 選定：
- 里程碑順序；
- 平台任務的時程與環境；
- 里程碑與 PR 的對應；
- 切換放行條件。

以上四題都照建議。

## 考慮過的選項

- **先蓋完一層再做下一層**：否決。違反 ADR 0008 的 tracer bullet；基礎建設的設計問題要等接上功能才會發現。
- **舊資料匯入延到切換前**：否決。擁有者要到最後才能用真實資料試用，匯入的問題最晚才浮現。
- **Debug 頁提早到 M2**：否決。M2 會過大；那時只有一個插件，插件開發工具用不太到。
- **Linux 從 M1 起全面驗證**：否決，M1 已經很重。
- **以 WSLg 驗收 Linux**：否決。它是 Weston 加 RDP：
  - 沒有托盤（microsoft/wslg #532）；
  - 鑰匙圈預設沒在跑；
  - 桌面歌詞的置頂與穿透測不準。
- **Mac 到貨前租雲端 Mac**：否決，只等約一個月，而且 M1 本身就會超過一個月。
- **里程碑不開 PR 子任務**：否決。每個 PR 沒有自己的驗收與檢查紀錄。
- **每個 PR 都完整走一次 brainstorm**：否決。M1 要核准十幾次，而且多是里程碑層級已定的事。
- **加開 GitHub Milestones 或 Projects**：否決。repo 沒有在用，與 Trellis 兩套也不會自動同步。
- **拿存下的基準數字比較**：否決。機器、模擬器、系統更新都會讓數字漂移。
- **效能不留誤差範圍**：否決，量測雜訊會卡住合格的版本。
- **試用 1 週或不設試用、4 週以上**：否決。前者讓要用一陣子才會碰到的問題落到所有使用者身上；後者拉長功能凍結。
- **切換後以降版退回**：否決。Android 降版要先移除 App，會刪掉私有資料。

## 決定

1. **結構**：
   - **里程碑任務**：`fmp-rewrite` 的 child。
     - 開工時走 brainstorm，擁有者核准一次 prd／design／implement；
     - implement 列出 PR 子任務與先後順序（Trellis 的 parent／child 不表達依賴）。
   - **PR 子任務**：里程碑任務的 child。
     - 一個分支、一個 PR，合進 `main`；
     - prd 只寫做什麼與驗收；PR 描述附 review 指南；
     - 合併後 `app/` 可編譯、測試全綠；
     - 在已核准的範圍內直接做，遇到未定的事才問。
   - **里程碑驗收**：Android 與 Windows 各做一次端到端實際操作，加上併入的實測項目。
   - **平台任務**：也是 `fmp-rewrite` 的 child。
   - **追蹤**：只用 Trellis 任務樹。清單與狀態在 `.trellis/tasks/09-26-fmp-rewrite/milestones.md`。
2. **排序原則**：
   - 縱向切片，每個里程碑結束時多一件可以實際操作的事；
   - 每個新增資料表的里程碑，同時補上那張表的舊資料匯入（M5 起）；
   - 各組設定的欄位清單（ADR 0011），在引入該組設定的里程碑定案。
3. **里程碑**（範圍、依賴、併入的實測見 `milestones.md`）：

   | # | 里程碑 | 做完能做什麼 |
   |---|---|---|
   | M1 | 骨架＋曳光彈 | Android、Windows 搜尋 B 站並連續播放兩首；接上所有基礎建設；YouTube.js 限時探針；`phase2-plan` §7 全部實測 |
   | M2 | 完整播放 | 佇列、播放頁 B、系統媒體控制、快取、背景排程器與啟動維護清單 |
   | M3 | 三音源、帳號與開發工具 | YouTube、網易雲、登入；插件庫與插件頁；Debug 頁與插件開發工具 |
   | M4 | 音樂庫與同步 | 歌單、匯入並刷新、外部歌單匹配、備份與還原 |
   | M5 | 舊資料匯入 | 匯入舊版資料與舊備份；擁有者以 dev flavor＋真實資料副本開始日常試用 |
   | M6 | 下載 | 下載，並匯入舊下載紀錄 |
   | M7 | 歌詞 | 多源、逐字、桌面歌詞、Android 懸浮，並匯入舊歌詞配對 |
   | M8 | 桌面整合 | 托盤、全域快捷鍵、開機自啟 |
   | M9 | 發版、更新與切換 | 應用內更新、使用者指南、放行條件全部通過，最後切換 PR |

   - M6、M7 互不依賴，可以對調。
   - 修訂（2026-10-01，M2 規劃時擁有者決定）：背景排程器從 M2 移到 M3，與第一個真工作（電台狀態）一起做；媒體 client 與封面磁碟快取從 M6 提前到 M2。範圍明細見 `milestones.md`。
4. **平台任務**：
   - **Linux**：M1 之後開。
     - 驗收在 VMware Workstation Pro（個人使用免費）的 Ubuntu LTS 桌面虛擬機，X11 與 Wayland 各一次；
     - 日常開發用 WSL2；
     - 之後每個里程碑在虛擬機跑一次冒煙測試。
     - 各平台實機驗證的時機與模式見 ADR 0027。
     - 修訂（2026-10-01，擁有者決定）：Linux 不在 M1 之後開，改為 Mac 到貨後與 macOS、iOS 一起在 Mac 上做，M2 先行；驗收的虛擬機與 X11／Wayland 的做法在該任務決定。
   - **macOS、iOS**：Mac 到貨後開。
     - 到貨前只靠 GitHub macOS runner 的編譯與 iOS 模擬器測試（ADR 0009）；
     - iOS 要不要實機、要不要付費帳號，在該任務決定。
5. **切換放行條件**（取代 ADR 0008 §決定 5 的功能清單來源）：
   1. **功能**：`questions.md` 勾「保留」的功能（E1–E17）與各 ADR 定下的行為全部在 `app/` 跑通，切換 PR 的 review 指南逐項列出。
   2. **效能**：
      - 同一台電腦、同一模擬器、同一份資料副本，以 `perf-baseline.md` 的命令把舊版與新版各量 5 次，比中位數；
      - 新版每項不得比舊版差超過 5%，超出就重量一次，仍超出則不放行。
   3. **資料**：
      - 真實資料副本完整匯入，並比對筆數（ADR 0010）；
      - 在模擬器與虛擬機上以資料副本從 v1.11.0 實際升級（ADR 0022）。
   4. **試用**：候選版當擁有者的主要播放器滿 2 週，期間沒有未解決的阻擋性 bug（資料錯誤、無法播放、當機）。
   5. **切換後**：以 2.0.x 經應用內更新往前修，不做降版。舊資料不自動刪除，可以重新匯入（ADR 0010）。

採用的慣例：
- Cockburn 的 walking skeleton 與 Pragmatic Programmer 的 tracer bullets；
- NewPipe 的「重寫期間舊版只收修正」；
- Firefox Fenix 以清單追蹤缺口並事先聲明資料風險；
- Spotube v5 以一次 major 版本為切換點。

## 後果

- 好的：
  - 每個里程碑結束時都有可實際操作的成果；
  - 每個 PR 小到能 review，又有里程碑層級的一次性核准；
  - 從 M5 起用真實資料試用，匯入的問題較早浮現；
  - 放行條件可重現、可量測。
- 壞的：
  - M1 很重，含全部基礎建設與 §7 的實測；
  - 切換前要實際量兩個版本、試用 2 週，功能凍結的時間拉長；
  - Linux、macOS、iOS 的功能會落後 Android 與 Windows。
- 之後要注意：
  - 里程碑的範圍若在開工時要大改，要回來修 `milestones.md` 並說明原因；
  - 切換 PR 同時刪除 ADR 0001–0007（`docs/adr/template.md` 的例外規則）與 `docs/audit/`。

## 如何確認

- 每個里程碑任務 archive 前，`milestones.md` 的狀態欄與驗收項目逐項打勾；未打勾的不能 archive。
  - 這是 review 點，不是自動閘門：里程碑驗收要實機操作，無法寫成測試。
- 切換 PR 的 review 指南必須附上四樣：功能清單逐項結果、效能對照表（5 次中位數）、匯入筆數比對、2 週試用期間的 bug 清單。
