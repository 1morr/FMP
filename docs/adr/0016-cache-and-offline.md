# 0016 — 快取與離線：一個可丟的快取庫、網址期限由插件回報、以請求結果判定離線

- 狀態：已採納
- 日期：2026-09-27
- 影響範圍：快取模組與 `cache.db`、圖片載入、串流解析、`resolveStream` 與封面 DTO、網路層的網路狀態、各頁的離線狀態、快取設定

## 背景

舊專案（`.trellis/tasks/archive/2026-09/09-27-design-cache-offline/research/current-state.md`，已以程式碼核對）：

- 圖片快取分三層互不統一，設定「圖片快取大小」只管磁碟那層，「清除圖片快取」不清記憶體層（`lib/main.dart:156-164`、`network_image_cache_service.dart:127-140`）。
- 串流網址存進 Isar（`track.dart:68-71`），但播放只看行程內快取；持久化的舊網址反而讓預取被跳過、切歌時退化成同步解析（`stream_resolution_service.dart:299-304`）。
  YouTube 期限寫死 1 小時（D9）。
- 歌詞快取有檔數上限與寫死的 5MB；排行只在記憶體，停用首頁顯示的音源仍在背景抓（B12）。
- 離線靠每 15 秒查三個公共 DNS（B10），只有一個全域 Banner，沒有頁面有離線狀態。

擁有者已勾選：B6 串流網址不進資料庫；D9 期限從網址讀；B10 改用系統網路狀態加請求失敗判定；B12 停用就不抓排行。

## 考慮過的選項

- **分類各自上限**（Namida、舊版）：否決。設定項隨類別增加，使用者分不清差別；改一個總上限。
- **串流網址持久化**：否決（B6）；舊版證明它沒被播放使用、還造成預取失效。
- **宿主解析各平台的期限參數**：否決。違反 ADR 0014「App 不懂特定音源」；改由插件回報（MusicFree 的 `cacheControl` 同樣把判斷交給插件）。
- **通用 HTTP 回應快取（`dio_cache_interceptor`）與搜尋結果快取**：否決。搜尋要新鮮，插件需要保存的東西用自己的 storage。
- **定時輪詢判斷離線**：否決（B10）。`connectivity_plus` 官方文件也說有介面不代表能上網，應以請求結果判斷。
- **手動離線模式（Finamp）、邊聽邊存（Spotube、Namida、MusicFree）、已下載內容容量管理**：新功能，依功能凍結列入待辦。
  邊聽邊存另有平台限制：`media_kit` 沒有此功能，需自建本機 proxy；`just_audio` 的 `LockCachingAudioSource` 仍是 experimental。

## 決定

1. **快取的定義**：可以隨時丟、丟了只會變慢的東西——圖片、歌詞內容、排行、串流網址。音樂庫與歌單、下載檔、播放與搜尋歷史、歌詞匹配結果、
   插件 storage 與憑證、設定都不是快取，不受快取上限與清除影響。
2. **統一快取庫**：一個快取模組擁有平台快取目錄（`getApplicationCacheDirectory()` 之下），以獨立的 drift 索引 `cache.db`（與主資料庫分開）加檔案保存；
   索引記鍵、類別、所屬插件、大小、最後存取、期限。檔案被系統清掉視為未命中。移除插件時刪除它的項目。
3. **一個總上限**：使用者設定「快取上限」128MB／256MB／512MB／1GB，預設由平台層宣告（桌面 256MB、行動 128MB，未設定＝跟著預設，ADR 0011）；
   超過時不分類別依最後存取淘汰。設定頁顯示各類用量與一個「清除快取」（含 Flutter 記憶體 `ImageCache`）。舊版兩個快取設定語意不同，不匯入。
4. **各類快取**：
   - 圖片：鍵為實際請求的 URL，經 ADR 0012 媒體 client；插件的封面 DTO 為多尺寸清單 `artwork: [{url, width?}]`，宿主挑最接近且不小於顯示尺寸的一張，縮放在解碼時做。
     以 `cached_network_image` 的自訂 cache manager 接到快取庫；接不起來就保留它自己的索引、由統一淘汰器依檔案大小一起淘汰。
     記憶體 `ImageCache` 大小由平台層宣告，不開放設定。
   - 歌詞內容：鍵為歌詞插件＋歌詞 id，只靠 LRU；匹配結果在主資料庫，淘汰後以存下的 id 重抓、不重新匹配。
   - 排行：鍵為插件＋榜單 id；先顯示快取並標「更新於 …」再背景刷新；只抓已啟用插件且在首頁啟用的榜單（B12），停用就刪掉快取。
5. **串流網址**：`resolveStream` DTO 帶可空的 `expiresAt`，由插件從網址本身讀（D9）。宿主只在記憶體保存（B6），鍵為曲目鍵＋分 P＋音質偏好、上限 64 筆，
   有效到 `expiresAt − 5 分鐘`；為空時 5 分鐘內有效。播放失敗作廢該筆；下載一律重新解析。預取與播放共用這一份。
6. **離線判定**：網路層擁有網路狀態——系統回報沒有網路介面（`connectivity_plus`，經平台層）即 `NoInterface`；30 秒內 3 次 `NetworkError` 且其間沒有成功即 `Unreachable`；
   任何請求成功或介面變化回到 `Online`。不輪詢；離線中不發背景請求，使用者操作照常發請求。
7. **離線時各功能**：音樂庫、歌單、下載管理、設定完整可用；已下載曲目照常播放，未下載的淡化顯示、播放時自動跳過並提示一次，整個佇列不能播就停止；
   歌詞與排行顯示快取，沒有就顯示離線狀態；線上搜尋、電台與直播、插件安裝與更新、登入顯示離線狀態、不送請求。
   一個全域離線提示加共用的離線空狀態元件；離線期間背景產生的 `NetworkError` 不跳 toast。

採用的慣例：MusicFree 讓插件決定網址可否重用；Finamp 的離線時功能降級；`connectivity_plus` 官方建議的「以請求結果為準」；
NewPipe／Spotube 的圖片快取交給 `cached_network_image` 系列；Android 官方對快取目錄「可能被系統清除、App 自行處理」的要求。

## 後果

- 好的：快取只有一個位置、一個上限、一個清除；丟掉快取不會掉資料；預取失效不再發生；網址期限跟著插件修，不必發 App；離線時每頁有明確狀態；不再每 15 秒查 DNS。
- 壞的：要自建快取索引與淘汰；圖片接到統一快取庫需要實作 cache manager 介面；每個播放類插件都要正確回報 `expiresAt`。
- 之後要注意：背景刷新與離線時的暫停、補跑見 ADR 0017；播放失敗的重試與跳過見 ADR 0018；邊聽邊存、手動離線模式、已下載內容容量管理列在功能凍結待辦。

## 如何確認

- 單元測試：串流網址快取的安全邊界、`expiresAt` 為空、作廢、下載不走快取；**預取後播放只解析一次**。
- 單元測試：快取庫跨類別淘汰到上限以下；檔案被刪視為未命中；清除後用量為 0；移除插件刪除其項目。
- 單元測試：網路狀態的轉換，且沒有計時器輪詢。
- widget 測試：各頁在離線時顯示離線狀態。
- 插件契約（ADR 0015）：播放類插件的 `resolveStream` 檢查案例斷言 `expiresAt` 與 fixture 網址內的期限參數一致。
- lint `fmp_layer_imports`（ADR 0015）：快取目錄只經快取模組取得。
