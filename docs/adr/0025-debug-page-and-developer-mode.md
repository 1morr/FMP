# 0025 — Debug 頁與開發者模式：記住的開發者模式、八區塊 list-detail、log 保留 7 天、只報告的資料檢查

- 狀態：已採納
- 日期：2026-09-28
- 影響範圍：`app/` 的 Debug 模組與路由、「開發者」設定組、log 檔格式與保留、診斷包、插件開發工具的版面、平台層能力 `pluginDevTools` 與檔案存檔／分享

## 背景

舊專案（`.trellis/tasks/archive/2026-09/09-28-design-debug-page/research/current-state.md`、`docs/audit/devtools.md`，已以程式碼核對）：

- **開發者模式**
  - 開法：版本列連點 7 次（`developer_options_provider.dart:49`）。
  - 只存在記憶體，沒有關閉入口；路由無條件註冊（`router.dart:246-263`）。
  - 實際只控制兩件事：設定頁入口、log 層級。
- **Debug 頁**
  - 記憶體磚：粗估數字，清除只清記憶體圖片快取。
  - log 層級。
  - Isar 檢視器：11 個 collection 各一次 `findAll()`，不能搜尋、不分頁。
  - 重設資料：直接 `isar.clear()`，不先備份。
  - 另有寫死的簡中與英文字串。
- **Log**
  - 記憶體 500 筆；
  - 檔案 2MB × 3，只限大小、沒有期限，內容是純文字行；
  - 「清除」只清記憶體。
- **`DataIntegrityRepository.scan/repair`**
  - 檢查 Track `uniqueKey`、DownloadTask `savePath`、Account `platform` 重複，以及 PlayQueue 超過一筆。
  - `lib/` 裡零呼叫點。
- **沒有的東西**：網路請求紀錄、播放狀態檢視、診斷包、音源健康檢查、插件開發工具。

已定的邊界：
- ADR 0011：log 門面、遮蔽、網路摘要、錯誤歷史、診斷包欄位。它寫明「Debug 頁與開發者模式的持久化由 Debug 頁的設計定」。
- ADR 0015 §4、§7：健康檢查與插件開發工具。它寫明插件開發工具的「版面由 Debug 頁的設計定」。
- ADR 0023：錯誤詳細頁。
- ADR 0016：快取的清除入口在設定頁。

擁有者在 `questions.md` 的勾選：J1「保留」、J2–J4「不確定」，並註明「可以按你推薦的來改」。
2026-09-28 選定：開發者模式、區塊、log 保留、資料檢查，四題都照建議。

## 考慮過的選項

- **開發者模式不記住（J1 原狀）**：否決。
  - 「詳細」（ADR 0023）、debug 層級（ADR 0011）、插件開發工具（ADR 0015）都依賴它；
  - 每次重啟要再點 7 次、重新載入插件資料夾。
- **可見的「開發者」設定項**（NewPipe、Home Assistant）：否決。一般使用者用不到；沿用 Android 系統的隱藏手勢。
- **release 版只留 log 與診斷包，其他限 debug build**：否決。正式版上的問題會看不到網路與播放狀態。
- **Debug UI 用 `TalkerScreen`、alice、`requests_inspector`**：否決。
  - 不是 App 的設計系統，也繞過遮蔽（ADR 0011）；
  - 三者都沒有 release 閘門。
- **`drift_db_viewer`**：否決。2.5 年沒發版，也做不到遮蔽。
- **在 App 內編輯資料庫**：否決。要做寫入介面，還會和 App 自己的寫入者衝突（舊版以 VM Service 寫入時踩過）。
- **重設前不備份（舊版）**：否決。一次誤按就無法挽回。
- **log 保留期限**：
  - 保留 3 天（Signal）：否決，週末前遇到、週末後才回報的問題就沒有紀錄。
  - 30 天、只限大小：否決，不常用的人會在本機留下幾個月的使用紀錄。
  - 做成可調設定：否決，對一般使用者沒有意義。
- **log 檔維持純文字行**：否決。錯誤歷史跨重啟讀回後分不出欄位，無法依錯誤類型、音源篩選。
- **移植 `scan/repair`**：否決。它查的四件事在新 schema 下由唯一鍵、主鍵、單列表擋住（ADR 0010、0020）。
- **自動修復損壞的資料庫**：否決。SQLite 損壞時能救回多少不一定，自動修可能默默丟資料。
- **每次啟動自動檢查**：否決。`integrity_check` 會掃整個檔案，拖慢啟動。
- **檔案監看自動重載插件**：否決。
  - 編輯器存檔到一半時會讀到半個檔案；
  - MusicFree、LX Music 都沒有這個功能。

## 決定

1. **開發者模式**
   - **狀態**：存在設定的「開發者」組（ADR 0011），兩個欄位：
     - `developerMode`：空值時 prod 為關、dev flavor 為開；
     - `logLevel`：空值＝info。
   - **開啟**：「設定 → 關於」的版本列連點 7 次。第 2 次起提示還差幾次，離開頁面後計數歸零。
   - **關閉**：Debug 頁「概覽」最上方的總開關。關閉時在同一筆寫入中：
     - `logLevel` 清為空值；
     - 卸載插件開發資料夾。
   - **它控制的東西**：
     - 設定頁的入口；
     - 錯誤提示的「詳細」；
     - log 層級可調到 debug；
     - Debug 頁的路由；
     - 插件開發工具。
   - **路由閘門**：開發者模式關閉時，Debug 頁路由一律 redirect 回設定頁。
2. **版面**：
   - 沿用設定頁的 list-detail（ADR 0024）：expanded 以上左列區塊、右顯示內容；較窄的畫面點進子頁。
   - 全部用 token 與 slang 字串。
   - release 版只要開了開發者模式，所有區塊都可用。debug build 另可用 drift 官方 DevTools extension。
   - 拿掉記憶體磚；快取留在設定頁，概覽放連結過去。

   | 區塊 | 內容 |
   |---|---|
   | 概覽 | 總開關、log 層級、版本／flavor／平台／資料目錄、快取用量連結、診斷包 |
   | Log 與錯誤歷史 | 第 3 點 |
   | 網路 | 第 4 點 |
   | 播放狀態 | 第 5 點 |
   | 音源健康檢查 | 第 6 點 |
   | 插件開發 | 第 7 點，只在平台層宣告 `pluginDevTools` 的平台出現（ADR 0009），先限桌面 |
   | 資料庫 | 第 8 點 |
   | 重設資料 | 第 9 點 |

3. **Log 與錯誤歷史**
   - **檔案格式**：JSON Lines，一筆一行。欄位：時間、層級、tag、訊息、error、stackTrace、結構化欄位。
   - **檢視**：
     - 預設看這次執行的記憶體歷史；開「含之前的紀錄」才在 isolate 解析 log 檔（最多 6MB）。
     - 篩選：層級、tag、文字。
     - 「只看錯誤」＝錯誤歷史，點一筆開 ADR 0023 的詳細頁。
   - **動作**：複製已篩選的內容；匯出 log 檔（走第 10 點的管道）；「清除 log」同時清記憶體與檔案。
   - **保留**：大小照 ADR 0011（2MB × 3）。最後修改超過 7 天的檔案，由啟動維護清單（ADR 0017）刪除；先到哪個限制就先刪。不做設定項。
4. **網路**
   - 資料來源是 log 門面裡的網路摘要（ADR 0011 §4），以 `info` 層級寫入，不另存一份。
   - 清單欄位：時間、方法、主機、路徑、狀態、耗時、大小、音源。
   - 篩選：音源、狀態碼類別（2xx／3xx／4xx／5xx／失敗）、文字。
   - 單筆詳細：遮過的 query、錯誤類型、對應的錯誤紀錄。
5. **播放狀態**：唯讀，播放控制仍只經 `AudioController`。
   更正（2026-10-01）：播放控制的唯一入口是 ADR 0018 的 `PlaybackController`，不是 `AudioController`。
   - 顯示內容：
     - ADR 0018 的 sealed 狀態（`Failed` 附 `AppError`）；
     - 曲目：插件 id、曲目鍵；
     - 串流：格式、位元率、容器、來源類型；
     - 音訊後端、輸出裝置、重試次數與下次重試時間；
     - 佇列：總數、目前索引、前後各 5 首、隨機與循環模式。
   - 位置每秒刷新一次。
   - 「複製快照」輸出 JSON，串流網址經遮蔽。
6. **音源健康檢查**
   - 對已安裝且啟用的插件，以真實連線跑 `checks.json` 的案例（ADR 0015 §4）。
   - 手動觸發：「全部」或單一插件；一次跑一個插件。
   - 結果：每個案例通過或失敗、耗時、`AppError` 類別。未登入的案例標「略過」。
   - 結果以 tag `health` 經門面寫入，不另外存。
7. **插件開發**
   - 以 `file_selector.getDirectoryPath` 選資料夾，路徑記在「開發者」組。
     - 資料夾中的插件標「開發中」，本次執行期間取代同 id 的已安裝插件；卸載後恢復已安裝版。
   - 「重新載入」按鈕：拆掉該插件的 JS runtime 再重建。
   - 每插件可切換真實、錄製、重播；錄製的 fixture 經遮蔽後寫到插件資料夾的 `fixtures/`。
   - 案例可單跑或全跑，顯示已遮蔽的回傳值與錯誤；log 預設篩成該插件的 tag。
8. **資料庫**
   - **唯讀瀏覽**：
     - 列出 `allTables` 與各表筆數；點進表以 `select(table)` 分頁，每頁 50 列。
     - 每個值經遮蔽函式；插件 storage 表的值整欄遮蔽。憑證在 secure storage，不在資料庫（ADR 0012）。
   - **「檢查」按鈕**，只報告：
     - `PRAGMA integrity_check`、`PRAGMA foreign_key_check`；
     - 孤兒曲目數（ADR 0019）、「檔案遺失」的下載數（ADR 0020），只顯示，處理交給各自的機制。
     - 有問題時提供「從備份還原」（ADR 0010）與「重設資料」。
   - 不在啟動時自動檢查。資料庫打不開時的處理屬於啟動流程，不在本 ADR 範圍。
9. **重設資料**
   - 範圍：
     - 清空：資料庫（含設定）、secure storage 中 FMP 的憑證、快取；
     - 不動：已下載的檔案與 sidecar、log 檔。
   - 流程：
     1. 以 ADR 0010 的備份格式自動備份到資料目錄的 `backups/`；
     2. 對話框列出備份位置，二次確認；
     3. 清空後重啟 App。
   - 備份失敗就不清空。
10. **診斷包**
    - 內容：ADR 0011 §6 的欄位，產生時組裝一次，輸出 `diagnostics.txt`、`diagnostics.json`，加上目前的 log 檔。log 寫入時已經遮蔽。
    - 動作：
      - 「複製」：只複製純文字摘要；
      - 「存檔」：輸出 `fmp-diagnostics-<時間>.zip`。桌面用 `file_selector.getSaveLocation`，Android 用系統的建立文件對話框；
      - 「分享」：用 `share_plus`，只在平台層宣告能分享檔案的平台顯示（Linux 與 Windows RS5 以下不能）。
    - 第一次匯出時提醒「送出前請檢查」，和 ADR 0023 的回報提醒共用同一個「不再提醒」設定。
    - 暫存的 zip 分享後刪除，殘留的由啟動維護清單清掉。

採用的慣例：
- Android 系統開發人員選項：連點版本號開啟、頁首總開關；
- Firefox `SecretDebugMenuTrigger`：剩餘次數提示、離開時計數歸零；
- LocalSend 的 HTTP Logs 頁；
- Immich、Signal 的 log 層級篩選與單筆詳細；
- Signal 的 log 保留期限與 zip 匯出；
- AppFlowy、Namida 的 zip 診斷包；
- LX Music「切換＝銷毀重建」與 VS Code「Reload Window」的插件重載；
- drift 官方 DevTools extension 作 debug build 的資料庫工具。

## 後果

- 好的：
  - 開發者模式跨重啟保留，也關得掉；
  - release 版可以當場查網路、播放、資料庫，並匯出已遮蔽的診斷包；
  - 錯誤歷史跨重啟、可依欄位篩選；
  - 本機 log 最多留 7 天；
  - 重設前一定有備份；
  - 不再維護守著不可能狀態的修復碼。
- 壞的：
  - 八個區塊要自己做 UI；
  - log 檔改成 JSON Lines，用文字編輯器直接看比較難讀；
  - 網路摘要以 info 層級寫入，會佔用記憶體歷史與 log 檔容量；
  - 資料庫損壞只能從備份還原或重設。
- 之後要注意：
  - 資料庫打不開時的啟動錯誤畫面，由啟動流程的任務決定；
  - Android 插件開發若要支援，需要 SAF 讀目錄的能力（file_picker 沒有），屆時另開 ADR；
  - 網路摘要若擠掉記憶體歷史中的錯誤，再考慮分開上限。

## 如何確認

- 既有 lint `fmp_platform_checks`（ADR 0015）：Debug 模組只讀平台層宣告的能力，不寫 `Platform.isX`。
- 單元測試：
  - 開發者模式：
    - 連點 7 次開啟並寫入設定；
    - 關閉時 `logLevel` 清空、開發資料夾卸載；
    - dev flavor 預設開。
  - log 保留：超過 7 天的檔被刪、未滿 7 天的保留，大小與天數同時作用。
  - log 檔：JSON Lines 讀回後欄位與寫入一致；遇到壞行略過，解析不中止。
  - 網路篩選：依音源與狀態碼類別。
  - 資料檢查：
    - 關掉外鍵後寫入一筆違反外鍵的列再打開，報告會列出它；
    - 乾淨的資料庫報告無問題。
  - 重設：備份失敗時不清空；成功時已下載的檔案仍在。
  - 遮蔽：播放快照、資料庫瀏覽、診斷包都不含假憑證與假簽名網址（併入 ADR 0011 的遮蔽測試）。
- widget 測試：
  - 開發者模式關閉時，直接進 Debug 路由會被 redirect；
  - 未宣告 `pluginDevTools` 的平台不顯示插件開發區塊；
  - 未宣告檔案分享的平台不顯示「分享」。
- 加入 Debug 頁的里程碑實測：
  - Windows release 版開啟開發者模式，重啟後仍開啟，再從總開關關掉；
  - 在 Debug 頁看到一次搜尋的網路摘要；
  - 匯出診斷包並以解壓工具打開。
