## FMP v1.10.0

The first release since v1.9.1 (8 July). Two months went into playback that
recovers instead of hanging, errors written for people rather than for
stack traces, and a radio player that finally behaves like the music player.

### Playback

- Stream resolution and media open now run under a time budget. A source that
  never answers fails with a message instead of leaving the player spinning.
- Playback that stalls mid-track is detected and reported. Previously it could
  sit there forever with nobody noticing.
- Gapless boundaries are handled by the backend holding the next track, with
  FMP following it across. Track identity and the metadata shown on the lock
  screen stay correct at the boundary.
- A stream URL that is still fresh is reused instead of being resolved again,
  and prefetched URLs now survive into the live queue.
- Reaching the end of the queue no longer re-fires completion.
- The chosen audio output device is remembered across restarts, and a failure
  to open it is reported as an output problem rather than blamed on the track.
- Restoring a saved queue goes through the same bounded handoff as every other
  playback path.

### Errors you can read

- Exceptions are mapped to user-facing messages before they reach the UI.
  Toasts and dialogs no longer print raw `ClientException` or `DioException`
  text at you.
- A track that failed to load is now told apart from one that is still loading,
  and covers and sections surface load errors instead of swallowing them.
- Transient image load failures are retried per URL.
- The desktop lyrics window says "no lyrics" instead of waiting forever.

### Sources

- Netease: a request that failed because you are not logged in is no longer
  reported as a VIP restriction.
- YouTube: authentication is retried on the same stream type before falling
  back to a different one.
- Stream expiry now uses the value the source actually reports.
- The home rankings no longer drop a source when space is tight.

### Windows

- System media controls no longer advertise seek, shuffle and repeat when the
  player cannot honour them, and skip controls are hidden during radio.
- The desktop layout — panel widths and the like — is remembered across
  restarts and is included in backups.
- The player layout responds to window height and to whether lyrics are shown.
- The detail panel is capped by ratio and has a real drag handle.

### Interface

- Settings moved out of the navigation bar.
- The radio player, its detail panel, station cards and info dialogs now share
  the music player's chrome instead of being a near-copy that drifted.
- Destructive actions use one confirmation dialog and one error colour.
- Toasts and snackbars go through a single builder with type-driven durations.
- Cover images pick a size-matched source instead of a fixed one, and the
  radio full-screen cover uses the full-resolution original on high-DPI
  displays.
- The mini player progress bar is reachable, and every icon button is labelled.

### Library and backup

- Backup import is all-or-nothing; a partial import can no longer leave the
  library half-written.
- Backups include the desktop layout settings.

### Under the hood

- The database schema is versioned rather than inferred from its shape.
- Logs are persisted to disk with rotation.
- The licence page lists the LGPL components (libmpv, FFmpeg).

### Upgrading

- On Android, stored logins are re-encrypted on first launch. This is
  automatic; if a credential cannot be read you are asked to sign in again
  rather than the app failing to start.
- Because of that re-encryption, **downgrading to v1.9.1 will most likely
  require signing in to all three sources again.**
